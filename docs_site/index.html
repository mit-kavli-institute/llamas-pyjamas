Products and stacking

Products
RSS files and cubes, per exposure — and deeper cubes from the combine

Each exposure reduces to one row-stacked-spectra file per colour on native per-fibre wavelength, plus its own cube. Combining the dithers then yields a deeper, registered cube of the whole field.

Stacking
Stacking happens afterwards, and resamples once

Interactively in the CubeViewer or headlessly with combineField. The single spatial and spectral resample happens only at that final step.

Setup & config

Every reduction is driven by a plain-text key = value config file. It can be hand-written, but the intended entry point is reduxSetupGUI: it scans a raw night, classifies every frame from its header, lets you correct the classification, builds the master bias, and writes the config.

What you run
python -m llamas_pyjamas.Utils.reduxSetupGUI RAW_DIR -o config.txt
What it produces
config.txt
slow_master_bias.fits
fast_master_bias.fits
QA output
At least one Science frame and all three Flat colours are assigned. Twilights, arcs and bias are optional but recommended for the best quality data products.

Both arguments are optional: omit the directory for a browse dialog, omit -o to write <raw_night>/llamas_redux_config.txt. The output directory defaults to <raw_night>/reduced/.

What it does

1
Scans the directory

Reads the primary header of every *.fits MEF — skipping white/diff quicklook products — and tabulates object, exposure time, type from PRODCATG, readout mode and the observer's comment.

2

obslog_usernotes.txt from the raw directory, in a lower pane.

3
Recommends flux standards

Science pointings landing on a catalogued spectrophotometric standard are cross-matched and pre-tagged Flux Standard. Overridable.

4
Role assignment

Select rows, click a role button; roles are colour-tinted in the table. Right-click a row to preview the raw MEF in DS9 (needs ds9 running).

5
Builds the master bias

Frames tagged Bias are median-combined per readout mode. Leave the role empty to use the packaged masters.

6
Writes the config

Unassigned keys are commented out so the pipeline falls back to defaults. Load Config maps an existing config back onto the table for revision.

The Configuration Options window

How it writes back

File and path role keys — flats, arcs, science, bias, output directories — are deliberately excluded; they stay owned by the main window's role buttons. The dialog seeds from the current config's active keys, or the catalog defaults. On OK each value is substituted and uncommented in place in the template, or appended if absent. Blank optional paths and "0 means unset" integers (ray_num_cpus, pixel_flat_saturation_threshold) are written back commented out. Opening the dialog is opt-in: untouched, Write Config behaves exactly as before and writes only changed keys.

Run the reduction

One command turns a night of raw frames into per-exposure RSS files. The pipeline is resume-aware, parallelises the heavy stages with Ray, and stamps headers so a second run skips what is already done.

What you run
python reduce.py config.txt
What it produces
{name}_RSS_{red,green,blue}.fits
{name}_whitelight_fullpipeline.fits
QA/ reports
QA output
The HTML wavelength-QA report per science frame — xshift curvature, arc residuals, OH-line residuals after sky subtraction.

Invocation

cd llamas-pyjamas/llamas_pyjamas
python reduce.py /path/to/raw_night/llamas_redux_config.txt

# equivalent, from anywhere
python -m llamas_pyjamas.reduce /path/to/raw_night/llamas_redux_config.txt

Set clobber = true to force a full rebuild instead of resuming from on-disk products, and ray_num_cpus to control parallelism.

QA reports

wavelength_qa defaults to true and writes one self-contained HTML report per science frame — every figure embedded as base64, no sidecar images — plus a CSV scorecard, into qa_output_dir (default {output_dir}/QA). It reports per-camera xshift curvature, arc-line fit residuals when refine_arc ran, and post-sky-subtraction OH-line residuals, with out-of-tolerance cells highlighted. QA failures never abort a reduction.

python -m llamas_pyjamas.QA.waveQA <..._sky1d_extractions.pkl> --qa-dir QA/ --label baseline
Known caveats

A resumed run that reuses existing extractions does not regenerate the reports. Use the standalone QA.waveQA CLI on the existing pickle.

If output_dir is unset the reports land in the package's own reduced/QA/ rather than beside your data. Set qa_output_dir explicitly.

Workflow · step 3 of 5

WCS correction

A Gaia-anchored per-fibre WCS, solved per exposure or per dither block, written back into the RSS on disk.

What you run
CubeViewer ▸ WCS ▸ Auto-register block…
or register_exposures(paths)
What it produces
Refined per-fibre RA/DEC in FIBERMAP and FIBERWCS of every colour, and in the white-light image WCS
QA output
Residual RMS < ~0.25″. The QA plot title reports solve type, star count and RMS per frame.

Background

Note

The combine places every fibre at its FIBERWCS position, so WCS accuracy sets the sharpness of the stacked PSF. Residual offsets between dithers blur the co-add and cannot be corrected later.

reduce.py writes only a provisional WCS from telescope pointing plus rotator angle. Real TCS pointing error is often 4–6″ — not good enough to co-add dithers cleanly.

How the solve works

01
Gaia cone search

Live query seeded by the rough WCS.

02
Fibre-space centroids

Fitted for the brightest sources — in fibre space, not on a gridded image.

03
Consensus matching

Trust comes from two or more stars agreeing on a common shift, or one dominant standard — not from shift magnitude.

04
Solve and write back

Offset, plus rotation per block. Stored on disk with the RSS; later stages just read it.

Because trust is by consensus rather than plausibility, a large-but-consistent TCS error is corrected safely instead of being rejected as implausible.

Running it

WCS ▸ Auto-register this exposure
Gaia solve for one frame.
WCS ▸ Auto-register block…
One rotation fit plus per-frame shifts for a whole dither group. The usual choice.
WCS ▸ Refine WCS interactively…
Manual fallback: Gaia sources overlay as green circles, click the star at the DS9 crosshair and it snaps to the flux-weighted fibre centroid. The block's rotation can be held fixed while only translation fits.
WCS ▸ Show registration QA
The QA plot for the current solve.
WCS ▸ Reset to rough (header) WCS
Revert to the provisional pointing solution.
 
from llamas_pyjamas.Utils.register import register_exposures

register_exposures(list_of_rss_paths)   # auto-groups by OBJECT + rotator, solves each block

The other entry points are register_exposure (one frame), register_block (a rotation-sharing group, optionally fixed_rotation=…), and reset_rough to revert.

DS9 display

Target
RMS < 0.25″

On the may26 fields, ~33 of 35 frames refine automatically.

Known failure mode
Rotation off by 180°

Fix with Auto-register block holding the correct rotation, or refine interactively.

Combine the dithers

Every fibre from every dither goes into one table — the super-RSS. Cubes, co-add images and depth maps are all views of that table, and the single spatial and spectral resample happens only here.

What you run
Combine ▸ Combine field into cube…
or Combine.combineField
What it produces
reduced/combined/<field>_cube_{blue,green,red}.fits
+ VAR · COVERAGE · NEXP
QA output
The coverage and NEXP maps, the transparency scale factors, and whether the stacked PSF looks as sharp as a single exposure.

Correct the WCS first — see step 3. Uncorrected dithers blur the co-add.

Dithered fields

A set of exposures on the same field, taken with small telescope offsets and optionally at more than one rotator angle to fill the ~7% inter-lenslet gaps. The pattern is chosen by the observer, so coverage is generally uneven across the field: the combine makes no assumption about it and records what was actually observed in the COVERAGE and NEXP maps rather than trimming to a uniform-depth region.

The super-RSS

Rather than resample each exposure and stack images, the pipeline gathers every fibre into one table, tagged with its native wavelength, its inverse-variance weight, its exposure, and its plate-solved RA/DEC. All deliverables are views of that one table.

TAGGED WITH
native wavelength · ivar weight · exposure · RA/DEC
VIEWS
cube · co-add image · narrowband · depth maps
RESAMPLES
once, at the very end

Transparency scaling

Weather changes between dithers. Before co-adding, the combine can scale every exposure onto a common photometric system using an in-field reference source: it measures that source's flux in each exposure and scales the fainter, cloudier ones up, adjusting the variance so inverse-variance weighting still down-weights noisier frames correctly. On a good field the corrections are small (±10%), but on a night with passing cloud they matter.

Running it

Combine ▸ Combine field into cube… → pick the dithers from the observation log → set the options. It builds a cube for every channel on one shared grid, opens it, and saves to reduced/combined/.

Callout — about the kernel FWHM

The gridding kernel fills the inter-lenslet gaps and lands the irregular dithered fibres on a regular grid, but it also softens the rendered image: effective image PSF ≈ √(source² + kernel²). Use ~0.9″ for faint diffuse emission, where it acts as a near-matched filter; drop to ~0.5–0.6″ for a sharper view of compact structure, at the cost of more holes and noise in shallow-coverage regions. This affects only the rendered cube or image — point-source optimal extraction works in fibre space and is not softened by it.

Products

Cubes — reduced/combined/<field>_cube_{blue,green,red}.fits

(RA, DEC, wavelength) with VAR, COVERAGE and NEXP extensions and a WAVELENGTH table. The header records the contributing RSS paths (NRSSFILE, RSSFILn), so re-opening the cube rebuilds the super-RSS on the fly — no giant file needed, and extraction runs on native fibre sampling rather than the gridded cube.

Co-add image

In image mode: a DS9-ready FITS with the same VAR/COVERAGE/NEXP maps.

Depth maps

COVERAGE counts fibres per pixel, NEXP counts distinct dithers: the deep-core / shallow-halo record. Broken fibres — a couple per exposure that read strongly negative — are masked as no-data by default so they don't punch holes in the co-add; --keep-bad-fibres disables that.

Known caveat — sky-subtraction striping

Faint diagonal striping in a deep co-add is an additive per-detector sky-subtraction residual, not a transparency effect, so transparency scaling correctly does not remove it. Because it is coherent across dithers it does not average down with more exposures either. It is an upstream sky-subtraction issue — the combine is faithfully co-adding the input residuals — and clean diffuse work at the faintest levels is gated by that separate, ongoing work.

Science products

Extracted from a stacked field: optimal spectra extracted in fibre space, a differential-refraction track, narrowband images, and an absolute flux anchor.

What you run
Extraction ▸ Optimal spectrum at crosshair
Combine ▸ Narrowband line image…
Extraction ▸ Anchor cube flux to Gaia…
What it produces
1-D spectra across three channels, continuum-subtracted surface-brightness images, an absolute flux scale
QA output
The PSF fit drawn into DS9, the DAR centroid track, the per-channel PSF budget, and the colour scatter of the Gaia flux ratio.

Optimal extraction

Put the DS9 crosshair on the source and take Extraction ▸ Optimal spectrum at crosshair. The extraction is PSF- and inverse-variance-weighted and runs on native fibre sampling — so the gridding kernel used to render the cube does not soften it.

Differential atmospheric refraction

A source's centroid walks with wavelength. The extraction tracks that walk rather than assuming a fixed aperture, which is what keeps the blue and red ends of a single spectrum photometrically consistent.

Narrowband images

Combine ▸ Narrowband line image… builds a continuum-subtracted surface-brightness image in a chosen line window. From the command line, combineField --band LO HI --units sb produces the same view of the super-RSS.

Absolute flux anchor

Extraction ▸ Anchor cube flux to Gaia (at crosshair)… ties the stacked flux to the true SED of an in-field Gaia source, fixing zero-point and aperture loss at once with a source already in the frame. Full detail on the Flux calibration page.

Flux calibration

A three-phase chain: identify the standards, build the sensitivity function from one, apply it to the science RSS. Then verify against an in-field Gaia source.

What you run
Sensitivity ▸ Build Sensitivity Function…
then Apply, or apply_fluxcal
What it produces
A sensfunc FITS carrying the standard's name, channels and airmass; FLAM and FLAM_ERR written back into each science RSS
QA output
Fit residuals in the build dialog, then the Gaia flux-ratio colour scatter — a slope means residual throughput or colour error.
Setup trap

reduce.py does not build or apply the sensitivity function. Standards tagged flux_standard_files are merged into the science list and reduced identically — there is no standard-specific code path in the pipeline. Calibration is a post-reduction step, by design.

Formalism

S(λ) = F_ref(λ) / ( C_obs(λ) / t_exp )

F_ref is the standard's known true flux; C_obs its extracted counts summed over the star's aperture.

The fit must follow the instrument, not the star

Two families of wavelength are masked before fitting: telluric absorption bands, which belong to the atmosphere rather than the instrument, and the standard's own strong intrinsic lines. LLAMAS optical standards are hot subdwarfs and white dwarfs (GD108 sdB, Feige110 DOp) whose broad Balmer and He absorption would otherwise drag the fit down — on GD108 the raw blue ratio swings ~12×, almost all of it Balmer.

The fit runs in log space, because S spans orders of magnitude and is far smoother logarithmically, using pypeit's robust iterative b-spline iterfit — the same fitter as the flat-field and sky steps — so outliers left by imperfect masking are rejected rather than followed.

Rationale

The VPH grating blaze features are a fixed instrument property — no moving parts — so the extra knots that capture them are established once and shipped in LUT/sensfunc_breakpoints.dat. Each night re-solves only the throughput on that fixed knot structure.

Standards used

GD108 (sdB) and Feige110 (DOp). Their intrinsic absorption is masked by default; the interactive mode is for whatever the defaults miss.

Building it

When a loaded RSS is a spectrophotometric standard, define an aperture on the star in DS9 exactly as for any spectrum, then open Sensitivity ▸ Build Sensitivity Function…. Two modes, same core:

AUTO
Defaults

The fit is already in place when the dialog opens, using the default telluric and stellar masks and a span-derived breakpoint spacing. Save to accept it.

INTERACTIVE
Manual masking

Drag on the plot to add a mask region, toggle the default masks, change the breakpoint spacing or spline order; fit and residuals redraw live before you Save. Use it where the default masks are insufficient.

The result saves as a sensitivity-function FITS carrying the standard's name, its channels, and its airmass.

Applying it

FLAM(λ) = ( SKYSUB(λ) / t_exp ) · S(λ) · E(λ)
E(λ) = 10 ^ ( 0.4 · k(λ) · (X_science − X_standard) )

E is the differential atmospheric-extinction correction. The standard's own extinction is already folded into S — the sensfunc is built without correcting the standard to zero airmass — so only the airmass difference is applied. That is why the sensfunc must record the standard's airmass: without it, extinction is skipped with a warning and the calibration is exact only when the two airmasses match. k(λ) is pypeit's bundled La Silla/CTIO curve, selected by observatory coordinates as the nearest match to Las Campanas — ~30 km away, same altitude.

Written in place

FLAM and FLAM_ERR are written back into the RSS — no new files, instrumental planes untouched. Each science RSS must be a single channel present in the sensfunc; the channel is read from the file's CHANNEL header, so blue, green and red files each get the matching channel.

Sensitivity ▸ Apply Sensitivity Function to files… — the same operation with a file picker: choose the sensfunc, then the science RSS files to calibrate.

 
python -m llamas_pyjamas.Postprocessing.apply_fluxcal SENSFUNC.fits RSS1.fits [RSS2.fits ...]
python -m llamas_pyjamas.Postprocessing.apply_fluxcal SENSFUNC.fits RSS.fits --no-extinction
python -m llamas_pyjamas.Postprocessing.apply_fluxcal SENSFUNC.fits RSS.fits --outdir calibrated/

Verification — the absolute Gaia anchor

Extraction ▸ Anchor cube flux to Gaia (at crosshair)… ties the stacked flux to the true SED of an in-field Gaia source, fixing zero-point and aperture loss at once with a source already in the frame — no separate standard needed.

G < ~17.6
Gaia DR3 XP spectrum

A flux-calibrated SED, so it is SED-independent — works for a quasar as well as a star. Needs gaiaxpy and network.

FAINTER
Broadband fallback

A coarse SED from Gaia G/BP/RP magnitudes, flagged approximate in the dialog.

DIAGNOSTIC
Colour scatter of the ratio

A slope flags residual throughput or colour error — or, for a variable quasar, an epoch mismatch.

Prefer a genuine star for end-to-end validation; quasar anchors carry a variability caveat.

← 5 · Science products CubeViewer
Capabilities

CubeViewer

A standalone PyQt6 application for postprocessing analysis of reduced products — and the home of registration, stacking, flux calibration and extraction.

python -m llamas_pyjamas.CubeViewer [file]

It is independent of the QuickLook/observing-log GUI in llamas_pyjamas.GUI: it imports read-only helpers from the reduction code and modifies nothing in it.

Relationship to DS9

Division of labour

CubeViewer collapses the loaded product over a wavelength window you choose, sends the image to DS9, and plots the spectrum of whatever spatial element you pick in the DS9 window. Stretch, colourmap, zoom and pan stay where they are already better.

DS9 is optional. The window opens, loads data and plots spectra without it; only image display and picking need it, and its absence is reported rather than fatal.

How it talks to DS9

Over the XPA messaging system, invoking the xpaset/xpaget command-line clients and piping in-memory FITS bytes on stdin — nothing is written to disk. pyds9 is deliberately avoided: unmaintained, undeclared, and it doesn't build on recent Python.

Setup trap — the XPA client tools

SAOImageDS9 bundles the XPA name server (xpans) but not the XPA client tools, and there is no Homebrew xpa formula — so xpaset/xpaget are frequently absent. CubeViewer searches $CUBEVIEWER_XPA_DIR, then $PATH, then the usual install locations, and raises an actionable error naming the fix rather than failing obscurely.

git clone https://github.com/ericmandel/xpa && cd xpa && ./configure && make && make install
# or install a packaged build (e.g. conda-forge), then put the binaries on $PATH
# or: export CUBEVIEWER_XPA_DIR=/path/to/them

Data model

Geometry-agnostic scenes

A SpectralScene interface has two implementations — fibres (cubeViewRSS) and rectilinear spaxels (cubeViewCube) — so every tool works on either.

Siblings load together

Opening one channel finds the others by name, so blue + green + red load together and cover ~3170–10051 Å.

Cuts are per fibre, not per column

Wavelength cuts are applied against each fibre's own WAVE row. The 2-D WAVE extension means fibres share no common grid, so a column slice would be wrong. Geometry is keyed on (BENCHSIDE, FIBER_ID) from FIBERMAP — never on row index.

Troubleshooting

SymptomLikely cause / fix
reduce.py errors on --configThe argument is positional: python reduce.py config.txt.
CubeViewer says the XPA tools are missingSAOImageDS9 ships xpans but not xpaset/xpaget. Build SAO's XPA package or set $CUBEVIEWER_XPA_DIR.
A frame won't register, or the rotation looks wrongWCS ▸ Refine WCS interactively…, or Auto-register block holding the correct rotation.
Missing-camera or extension errors on raw framesRun python -m llamas_pyjamas.DataModel.validate on the MEF first.
Only the green cube appearsBuild with the CubeViewer combine (shared grid, all channels), or combineField without --channels.
Negative "holes" in the co-addBroken fibres — masked by default. Do not pass --keep-bad-fibres.
Co-add looks noisier than a single exposure in the redCoherent sky-subtraction residuals; they don't average down.
Displayed image looks soft, PSF too bigThe gridding kernel softens only the rendered image. Lower the combine Kernel FWHM.
No QA reports after a re-runQA regenerates only when extraction reruns. Use the standalone QA.waveQA CLI.
QA reports aren't next to my dataoutput_dir unset → they land in the package's reduced/QA/. Set qa_output_dir.
Gaia anchor says approximateThe source has no Gaia XP spectrum (too faint); it fell back to broadband photometry.
